# 自动上下文压缩

普通使用只需配置触发比例。默认在可用输入预算达到 80% 时压缩历史对话，不再按 50 条消息触发摘要。

```properties
liteflow.agent.harness.compaction-threshold=0.8
```

无法获取模型资料，且没有显式容量或模型自身报告的容量时，使用可配置的兜底策略。512K 表示 524,288 token。

```properties
liteflow.agent.harness.compaction-fallback-context-window=524288
liteflow.agent.harness.compaction-fallback-threshold=0.9
```

两个比例都必须大于 0、小于 1，兜底上下文大小必须为正整数。Spring Boot、Spring Boot 4 和程序化 `HarnessConfig` 使用相同配置。

## 模型资料的获取与缓存

模型资料在 Agent runtime 初始化时准备。如果 Agent 采用懒初始化，这一步发生在第一次执行该组件时，早于实际模型请求。

框架通过模型接入时保留的服务商信息和实际模型标识查询 Models.dev。已知官方接入地址会映射到对应的服务商；自定义网关不会仅凭模型名称冒用官方服务商的容量。

容量优先级为：显式 `ModelSpec.contextWindow(tokens)`、Models.dev 缓存、已知服务商 SDK 或自定义 `Model` 报告的容量、配置的兜底容量。自定义端点可用 `contextWindow(tokens)` 声明部署容量；只有确认其限制与指定服务商一致时，才使用 `modelCatalogProvider(providerId)` 指定 Models.dev 的服务商标识。

本地资料默认保存在 `${user.home}/.liteflow/model-catalog/models-v1.json`。需要更换缓存目录时，可设置 JVM 系统属性 `liteflow.agent.model-catalog.cache-dir`。该目录独立于会话工作区。

- 已有有效缓存时直接使用；没有缓存时，首次初始化尝试下载一次。同一 JVM 内共享下载和内存缓存。
- 网络响应直接流式解析并裁剪为服务商、模型标识、上下文、输入和输出限制；原始完整 JSON 不会构造成内存对象树，也不会保存到磁盘。
- 本地文件保留所有已收录模型的精简资料。首次查找某个模型时流式扫描文件，内存最多缓存 256 条查询结果，包括不存在的模型。
- 模型调用中的容量检查命中内存缓存时不读文件、不访问网络；超过缓存上限而被淘汰的条目，下次使用时重新查询一次。后台线程每 6 小时检查资料更新，发送 ETag；未变化时使用 304 响应，不重新下载正文。
- 查找尚未收录的模型时尝试提前刷新；所有提前刷新和失败重试共享 5 分钟冷却期。网络不可用时保留旧缓存，或使用兜底值，不中断 Agent 初始化。
- 下载内容先写入同目录临时文件，完整解析成功后原子替换。无效 JSON、空目录数据、HTTP 错误不会覆盖旧资料。后台更新会更新当前缓存中的模型；之前采用兜底且仍在缓存中的模型获得有效资料后，自动改用正常压缩比例。
- 资料请求不携带模型 API Key、提示词或会话内容。首次连接超时为 3 秒，读取超时为 5 秒。

Models.dev 属于社区维护的资料库，在线刷新只能获得它已收录的数据。在线接口目前返回全量数据；HTTP 压缩减少传输量，ETag 减少无变化时的下载量，客户端流式裁剪控制内存占用。

## 压缩预算与执行

触发比例作用于可用输入预算。框架结合模型的总窗口、独立输入限制和输出限制计算预算，为本次输出和本地估算误差预留空间。因此 90% 表示可用输入预算的 90%，并非不考虑输出预留而直接填满总窗口的 90%。

已有 `maxTokens` 或 `maxCompletionTokens` 配置时使用其输出预算；没有配置时，框架自动选择受模型输出限制约束的预算。系统提示、工具定义、当前输入、历史消息、工具结果和结构化输出 schema 都参与本地 token 估算。估算不等于厂商 tokenizer 的精确计数，多模态内容也仍是本地估算。

检查发生在模型路由完成之后。主模型首次响应失败而切换 fallback 时，会按备用模型的容量和输出选项重新检查、必要时再次压缩。

压缩复用 AgentScope 的摘要、历史归档和工具调用配对保护；自动计算近期消息保留预算。摘要完成后再次检查容量，满足预算后才替换工作上下文。摘要失败保留原上下文；单条超大输入、系统提示或工具定义无法通过压缩历史解决时，返回明确错误，避免发送已知超出预算的请求。

原有 `compactionConfig()` 已标记弃用。覆盖该方法并返回非空配置时仍走旧策略，便于现有应用迁移；新应用使用上述比例配置即可。默认路径由 LiteFlow 安装自适应压缩中间件，替换 AgentScope 默认压缩中间件。
